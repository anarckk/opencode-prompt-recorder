opencode-prompt-recorder 功能设计与实现原理

OpenCode 插件 —— 自动记录用户提示词到本地文件系统（会话合并）

一、概述

opencode-prompt-recorder 是一个为 OpenCode AI 编程助手设计的插件，核心功能是自动捕获并持久化用户在聊天对话中发送的提示词到本地文件系统。它作为审计日志、训练数据收集和会话历史工具，无需用户任何手动操作即可后台静默运行。

💡 项目地址： https://github.com/anarckk/opencode-prompt-recorder  |  版本：1.6.0  |  作者：anarckk  |  许可：MIT

核心价值

  • 审计追踪：完整记录每一次与 AI 的交互过程，便于事后回溯
  • 训练数据收集：积累真实用户提示词，可用于模型微调或 prompt 工程优化
  • 会话恢复：对话按时间组织，便于回溯
  • 零配置：安装即用，无需额外设置

二、架构设计

插件采用事件驱动 + 函数式闭包的架构模式。整个插件是一个符合 @opencode-ai/plugin 的 Plugin 接口的工厂函数，内部使用 JavaScript 闭包来维护运行时状态。

2.1 事件驱动模型

插件注册一个统一的 event 异步处理器，监听三种事件类型：

事件类型触发时机处理动作
message.updated消息元数据更新时提取 messageID to role 映射存入 Map，供后续事件使用
message.part.updated消息内容部分更新时核心逻辑：检查 role、去重、按 session 缓存写入或追加
session.updated会话更新时写入版本化的 readme 文件（仅首次触发）

这种设计的主要优势：

  • 松耦合：每种事件独立处理，互不干扰
  • 状态隔离：闭包内的 messageRoleMap、processedMessageKeys、versionFileWritten、sessionFileCache 为每个插件实例私有
  • 被动监听：无需轮询或主动调用，完全由 OpenCode 运行时驱动

2.2 核心数据流

一次完整的用户提示词录制过程如下：

sequenceDiagram
    participant U as User
    participant OC as OpenCode
    participant PR as Plugin
    participant FS as File System

    U->>OC: 发送提示词
    OC->>PR: message.updated
    Note over PR: 记录 messageID-role
    OC->>PR: message.part.updated
    Note over PR: 提取 text sessionID
    PR->>PR: 按 session 缓存/查找文件路径
    alt 首条消息
        PR->>FS: mkdir + writeFile（含 SessionID）
    else 后续消息
        PR->>FS: appendFile（追加内容）
    end
    FS-->>PR: 写入完成
图 1：用户提示词录制时序

关键设计决策：

  • 仅录制用户消息：通过 role === "user" 过滤，忽略 AI 回复和系统消息
  • 快速失败：缺少 sessionID 或 text 为空时直接返回，不执行文件操作
  • 延迟写入：先做所有检查和查找，最后一次性写入，减少文件操作次数
  • 会话缓存：sessionFileCache 缓存 session→filepath 映射，后续消息直接追加，避免重复目录计算和 IO

三、核心模块详解

整个插件的源代码位于单个文件 index.ts（226 行），由多个函数/模块组成。

3.1 事件监听与角色解析

由于 message.part.updated 事件的 payload 结构在不同版本的 OpenCode 中可能变化，role 字段可能在多个位置出现。插件使用四级回退策略逐级尝试：

let role = messageRoleMap.get(messageID)
if (!role) role = part.message?.role
if (!role) role = info?.role
if (!role) role = info?.message?.role

message.updated 事件先于 message.part.updated 到达，因此插件在第一个事件中就把 messageID to role 存入 messageRoleMap，供第二个事件使用。这是一个跨事件的状态共享模式。

3.2 文件存储与目录组织

所有录制的提示词存储在项目根目录的 .agent/prompts/ 下，按日期分层组织：

.agent/prompts/
  2026/
   06/
    05/
      2606050943-What is AI.md

文件名格式：yyMMddHHmm-{topic}.md

片段来源说明
yyMMddHHmmformatDate()首次消息的日期和时间，确保文件名按时间排序
topicsanitizeFilename(text)首条提示词前 40 字符（净化后）

会话合并机制：同一 session 的多条消息合并到同一个文件，以首条消息的主题命名。后续消息通过 sessionFileCache（Map<sessionID, filepath>）缓存文件路径直接追加，避免重复 IO。

文件内容格式：

============ SessionID: ses_xxxxx ============

============ HH:mm ============

{提示词正文 1}

============ HH:mm ============

{提示词正文 2}

3.3 去重机制

由于 message.part.updated 事件在流式传输中可能多次触发，插件使用 Set 存储已处理的 messageID:text 组合键：

const dedupeKey = "${messageID}:${text}"
if (processedMessageKeys.has(dedupeKey)) return
processedMessageKeys.add(dedupeKey)
flowchart TD
    In[收到 message.part.updated] --> Key[构建 key]
    Key --> Dup{processedMessageKeys 已包含?}
    Dup -->|Yes| Return[直接返回]
    Dup -->|No| Add[加入 Set]
    Add --> Write[继续写入文件]
图 2：去重判断流程

这种方案在插件运行期间有效。如果 OpenCode 运行时重启，Set 会被清空，但文件系统是持久化的，追加写入不会产生重复。

3.4 文件名安全处理

sanitizeFilename() 函数将用户提示词转换为安全的文件名片段：

function sanitizeFilename(str) {
  const firstLine = str.split('\n')[0].trim()
  const cleaned = firstLine.replace(/<[^>]*>/g, '').replace(/\s+/g, ' ').trim()
  const result = cleaned.replace(ILLEGAL_FILENAME_CHARS, '').substring(0, 40).trim()
  return result || 'untitled'
}
处理步骤说明
取首行多行提示词只取第一行作为文件名
剔除 HTML 标签移除 <system-reminder> 等系统注入标签
合并空白连续空白替换为单个空格
剔除非法字符移除 <>:"/\|?* 以及控制字符
截断 40 字符防止文件名过长，取前 40 个字符
trim 修剪去除首尾空白
空值回退如果结果为空，使用 untitled 作为默认主题

3.6 版本信息与 Readme

当 session.updated 事件首次触发时，插件在 .agent/ 目录下生成 opencode-prompt-recorder-readme.txt，包含版本号、作者信息和项目地址。通过 versionFileWritten 布尔标记确保只写入一次。

✅ 设计特点： 版本号从 dist/package.json 动态读取，确保编译打包后的版本信息始终与发布版本一致。如果读取失败则回退为 "unknown"。

五、配置与使用

安装

npm install -g opencode-prompt-recorder
# 或
bun add -g opencode-prompt-recorder

配置

在项目根目录的 opencode.json 中添加插件声明：

{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-prompt-recorder"]
}

运行机制

  • 每次用户发送提示词，插件被动接收事件，无需任何手动操作
  • 提示词文件写入项目根目录的 .agent/prompts/
  • 同一 session 的提示词合并到同一个文件，以首条消息主题命名
  • AI 回复不会被记录（仅录制 role 为 user 的消息）

依赖要求

组件最低版本
OpenCodev0.15.0
Node.js 或 Bun-
⚠️ 注意事项：
  • 插件需要项目根目录的写入权限以创建 .agent/prompts/ 目录
  • 文件名中的特殊字符会被自动清理，过长提示词只取前 40 字符
  • 去重机制仅在插件进程生命周期内有效，重启后 Set 清空
