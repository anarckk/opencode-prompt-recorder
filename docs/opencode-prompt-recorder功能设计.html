opencode-prompt-recorder 功能设计

OpenCode 插件 — 自动将用户提示词和 AI 问答写入本地文件

一、概述

订阅 OpenCode 事件，当用户发送消息或 AI 通过 question 工具交互时，自动将内容保存到 .prompts/yyyy/MM/dd/ 目录下的文本文件中。同一会话的多条消息合并到同一个文件。零配置，装即用，不联网，数据仅存本地。

项目地址： https://github.com/anarckk/opencode-prompt-recorder  |  版本：1.8.4  |  许可：MIT
维度说明
语言TypeScript (ES2022)
运行时Node.js / Bun
依赖仅 peer dependency：@opencode-ai/plugin >=0.15.0
代码规模index.ts ~347 行 + updateOps.ts ~183 行，零外部运行时依赖
构建esbuild

二、事件处理

注册一个统一的 event 处理器，监听四种事件：

事件触发时机做什么
message.updated消息元数据更新提取 messageID → role 映射，存入 Map（仅存 user 角色）
message.part.updated消息内容更新核心逻辑：过滤角色、去重、跳过 task 子会话、记录 question 工具问答、写入或追加文件
session.created会话创建捕获会话标题存入 sessionTitleMap；若对应文件已创建则重命名以匹配标题
session.updated会话标题变更捕获标题变更；若文件已存在则重命名；若文件未创建则存入 pendingRenames 待文件创建后应用

三、文件存储

  • 目录结构：.prompts/yyyy/MM/dd/，按首条消息的日期决定目录
  • Task 子会话：子 agent 会话的提示词直接丢弃，不记录
  • Question 工具：AI 通过 question 工具提问时，提问内容和用户回答一并记录，格式为 [Question Tool] 块
  • 写入方式：同一会话首条消息创建文件（writeFile），后续消息追加（appendFile）
  • 缓存：sessionFileCache 缓存文件路径，避免重复目录计算。进程重启后 cache 为空，通过 findSessionFile() 按 sessionID 扫描已有文件复用
  • 跨天：每条消息时间戳包含日期（yyyy-MM-dd HH:mm:ss），目录以首条消息日期为准

四、命名规则

文件名：yyMMddHHmmss-{主题}.txt

  • 主题来源：优先用会话标题（从 session.created/session.updated 事件获取）；标题不存在时回退到首条消息文本
  • 延迟重命名：若文件创建后标题才到达（标题由 AI 后续生成），自动重命名文件。竞态处理：事件到达早于文件创建时通过 pendingRenames 队列暂存，文件创建后立即应用；5 秒后通过 SDK client 查询标题兜底
  • 文件名净化：移除 <>:"/\|?*、控制字符、Unicode 控制字符（零宽空格/BOM/方向覆盖等）、HTML 标签；截断至 40 字符；空白时回退为 untitled

五、错误处理

场景处理
目录创建 / 文件写入失败异常传播到事件循环，OpenCode 自动重试
debug log 写入失败console.error 报告，不抛异常
事件 payload 缺少字段多层 fallback 逐级尝试，全部失败则跳过
synthetic / ignored 部件误入主动跳过
文件重命名失败console.error 记录错误，不阻塞后续流程

调试日志：设置 PROMPT_RECORDER_DEBUG=1 后写入 .prompts-log/log.txt。

六、边界情况

场景处理
空文本提示词跳过不写入
纯空白 / 特殊字符文件名回退为 untitled
超长标题（>40 字符）截断至 40 字符；标题为空时回退到首条消息文本
系统注入标签（海马体等）isSystemInjected() 检测并跳过
并发消息事件processedMessageKeys（messageID + 文本）去重，超过 2000 条或 24h 后自动裁剪
跨天会话按首条消息日期决定目录
插件进程重启内存缓存清空，findSessionFile() 扫描已有文件复用
OpenCode 版本升级导致事件结构变化四层 role fallback 保持兼容
重命名冲突自动追加随机后缀

七、数据流

sequenceDiagram
    participant OC as OpenCode Runtime
    participant PR as Plugin
    participant FS as File System

    OC->>PR: message.updated
    Note over PR: cache role map

    OC->>PR: message.part.updated (type=text, role=user)
    Note over PR: filter → dedup → lookup cache
    alt first message in session
        PR->>FS: mkdir + writeFile(session header)
    else subsequent messages
        PR->>FS: appendFile(time header + text)
    end

    OC->>PR: message.part.updated (type=tool, tool=task)
    Note over PR: track child sessionId

    OC->>PR: message.part.updated (type=tool, tool=question, completed)
    Note over PR: format Q&A → append to file

    OC->>PR: session.created
    Note over PR: capture session title

    OC->>PR: session.updated
    Note over PR: capture title change
